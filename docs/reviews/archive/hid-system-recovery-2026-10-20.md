## 2. 逐条发现与处理

- CR-79：传输封装从静态元数据文件拆出，`IHidIo` 隔离原生 I/O，`HidIoResult` 区分普通等待超时与明确失效。读写等待超时不抹掉底层在途任务；同步 feature 也有计数，错误在原生调用返回处获取，关闭失败保持隔离。
- CR-79：基类观察到故障后推送离线副本，再关闭/等待旧会话收尾，才允许按原协议重开。探测失败、重复接口、同路径和同物理身份别名都不能绕过收尾屏障；正常静音不重开。Haute 删除私有直接换句柄逻辑，统一复用该路径。
- R1/R2：无新增硬件命令或插件。原开关、候选过滤和探测协议保留；写入恢复必须等待熔断到期，并有独立重开预算。普通写入插件的新端点不进入恢复阶段探测，也不在四个阶段反复调用写入型 Poll。
- R3/R7：退役状态与快照有锁，旧监听结果不能回写；同可信 ID 的恢复保留熔断与过滤状态，新增异常电量不能通过新 Probe 建立无条件基线。实际物理身份仍依赖各插件既有实现，不按名字迁移。
- CR-78：现有隐藏窗口注册电源、当前会话、HID 接口变化，仅把信号送入纯 .NET 调度器。锁屏不触发；恢复与解锁事件合并成有界阶段，不延后、不重叠，慢轮次跳过错过的阶段，长睡眠后的旧计时器被代次拒绝。部分注册失败只重试缺失注册，不叠加订阅。
- R4/R5/R8：退出先禁止新 I/O 并关闭登记过的句柄，字典收尾在共享 pass 之后；旧 I/O/监听结束才释放认领。失败有日志与计数；分类、预算、调度与真实基类均链接到零 WinRT 核心测试项目。

## 3. 需要修正或遗漏的部分

CR-72 尚未实现。同步原生调用如果不返回，仍可占住共享 pass；本批选择保留隔离与认领，不用外层超时后开启另一个可变插件会话。等待中的新探测可能延后，这不是所有设备已经不会互相影响的证明。

CR-82/83 仍未实现。保留最后电量不等于电量新鲜；路径 ID 也不能证明换口后的物理同一性。只有已经提供芯片/可信标识的插件能核实替换身份。罗技独立插件不进入新基类恢复路径，未扩大到罗技生命周期修复。

现有退出入口仍会调用 `Environment.Exit`，不能宣称不可返回的原生调用或失败的 Close 已全部优雅结束。已登记句柄会先尝试关闭，正常可收尾路径按屏障释放；异常边界有日志并待真机核实。
